# Requirement Traceability Matrix

**Document Version:** 3.1
**Last reviewed:** 2026-11-15 (code on `main` at `72a4788`)

Version 1.0 of this file was written at project start and marked nearly everything NOT IMPLEMENTED. This version reflects the code on `main`. Paths are relative to `server/src/` (server) and `client/src/` (client). Overall narrative: [../implementation/current_state.md](../implementation/current_state.md).

"Tests" lists automated coverage only: **planner suites** = `server/src/features/planner/__tests__/` (11 engine tests + 15 adversarial scenarios); **e2e** = Playwright specs in `e2e/tests/`. "Swagger" covers `server/src/docs/swagger.yml`, which now documents every route (generated from the zod schemas by `npm run docs:generate`; `server/test/openapi.test.ts` fails if a route is missing, the file is stale or the document is invalid), merged in #22 (`ecafef7`). Request bodies come from the same zod schemas the routes validate with; responses are documented only as the generic success/error envelope. **unit** = `server/test/*.test.ts`; **smoke** = `scripts/smoke.d/*.sh` (real MongoDB, after merge). Everything marked complete or partial below is on `main` (`a4ebba3`).
